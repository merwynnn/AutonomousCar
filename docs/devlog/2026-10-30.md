## Key decisions

- Sensor realism is a first-class requirement: default is `realistic`, with
  latency-aware message delivery and no ground-truth leakage.
- Production SLAM is C++17/Eigen/pybind11; Python reference is for tests.
- Python 3.11 is pinned because PyBullet has no cp312+ wheels.
- The dashboard is a monitoring client, not a physics engine.

## M1 result — PyBullet vertical slice

- Added a custom 1/10 4WD Ackermann URDF (`assets/urdf/generic_1_10_4wd.urdf`)
  with front steering knuckles, four wheel joints and a 1.8 kg chassis.
- Built the PyBullet world: floor, 768 static wall boxes from the track polyline,
  fixed 240 Hz physics, wheel friction, steering servo and 4WD velocity control.
- Implemented the raycast lidar: 720 beams, per-beam timestamps, motion
  distortion, range/angle noise, quantization, divergence, intensity, dropouts,
  dead beams, wall-height occlusion and latency.
- Implemented three ultrasonic sensors with cone sampling, noise, latency,
  specular dropouts and cross-talk.
- Added the wall-follow controller, manual WASD driving and a latency-aware
  control loop that holds the last command while a scan is in flight.
- Added race timing with start-line arming (a small start roll no longer counts).
- Dashboard now shows PyBullet mode, steering, sonars, progress/lateral offset,
  auto/manual modes and the M1 milestone.
- Acceptance: 5 laps in 148.34 s (29.52, 29.89, 29.68, 29.46, 29.79 s), zero
  penalties, 94.8 s wall time.
- 20 Python tests + C++ CTest pass; ruff/mypy clean; frontend builds.

## Lessons

- Holding the last command during sensor latency matters: braking to zero while
  waiting for a scan doubled the lap time.
- Live mode needs one lidar sub-ray per beam to stay near real-time;
  high-fidelity mode keeps three for edge/mixed-pixel realism.
- The start-line projection can wrap to the end of the loop; lap counting must be
  armed by actual distance travelled, not by progress alone.
- The wall-follower is stable but slow on the waist corners; a proper racing line
  and speed profile are the next step.

## M3 progress — C++ SLAM front-end and live map

- Replaced the SLAM skeleton with a working C++17 pipeline:
  - log-odds occupancy grid (5 cm);
  - chamfer likelihood field;
  - coarse/fine correlative scan matching with a motion prior;
  - per-beam deskew using the odometry/IMU twist;
  - pybind11 bindings and a Python `SlamPipeline` with base64 map export.
- Fixed the lidar motion-distortion model: hit points are now transformed back
  into the scan-start frame, so the scan is genuinely distorted and deskewable.
- Added live SLAM integration: every scan updates the map, the dashboard renders
  the occupancy grid, a blue SLAM ghost/trail, ATE and scan time.
- Added `awake-sim slam-bench` and `tests/test_slam_pipeline.py`.
- Benchmark (8 s, 81 scans): 2.89 cm mean ATE, 5.27 cm max, 14.2 ms mean scan,
  18.9 ms p95. Live dashboard: 0.8 cm ATE, 28.7 ms/scan under telemetry load.
- Screenshot: `docs/assets/2026-10-30-m3-slam.png`.
- 24 Python tests + C++ CTest pass; ruff/mypy clean.

## Lessons

- Without deskewing, the map smeared and the matcher drifted by metres.
- A motion prior around odometry is essential on repetitive wall geometry; it
  prevents jumps to the wrong wall segment.
- Subsampling points for the coarse search plus a fine full-point search keeps
  p95 under 20 ms on this laptop.
- The current result is front-end tracking, not full SLAM: there is no active
  loop closure or MCL yet.
- Added realistic drifting odometry and an SE(2) pose graph with keyframes and
  a tested optimizer.
- Attempted automatic loop closure with local submap matching. It works on a
  synthetic graph but produces false positives on the repetitive pipe track:
  the car can match a look-alike bottom straight while 1–3 m away from the
  candidate. A forced start-pose closure was explicitly rejected as cheating
  (it resets the car to a known pose instead of estimating it from sensors).
- Disabled automatic loop closure until a reliable descriptor/landmark is
  available. The pose graph remains ready for a trustworthy detector.
- Added a 400-particle MCL on the occupancy likelihood field:
  - odometry-increment motion model;
  - likelihood weighting, low-variance resampling, ESS/spread diagnostics;
  - runtime on/off/reset, independent of the loop-closure toggle.
- Added debug layers and live toggles to the dashboard: map, SLAM, MCL,
  particles, odometry, GT trail; MCL and experimental loop closure off/on.
- MCL benchmark (12 s, drifting odometry): SLAM 22.6 cm mean ATE, MCL 22.0 cm,
  MCL max 41.1 cm, ESS 281/400, spread 0.20 m. MCL tracks the map but cannot
  correct map drift.
- Fixed a Playwright selector collision between “Reset” and “Reset MCL”.
- Added GT/odom/MCL localization modes and MCL-driven pure pursuit. At a
  conservative 1.2 m/s safe line: GT 20.12 s, MCL 20.40 s, odometry DNF.
- Switched the mapping lap to **MCL control** as well (no GT): one lap 20.81 s,
  map seam 8.3 cm; one-lap MCL race 20.15 s.
- Five-lap sensor-only map/race: **DNF after 1 lap**. MCL drift across laps is
  the blocker; the one-lap map is good but sustained MCL tracking is not.
- Added a dashboard car-view selector: Actual / Controller / SLAM. The main car
  is the actual physics body; controller/SLAM views show the estimate with an
  orange actual-car ghost.
- The speed-limit slider now applies to pure pursuit as well as wall-follow.
