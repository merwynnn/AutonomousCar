# 2026-11-01 — Portable onboard runtime and shared estimator

## Goal

Split host-only simulation code from code that can run on the Raspberry Pi, and
make the simulator's odometry consume the same raw sensor chain the real car
will have.

## What changed

- Added `onboard/`:
  - `api.py`: `Observation`, `Actuation`, `SensorFrame`, `StateEstimate`,
    `RobotAPI`, raw lidar/ultrasonic/IMU/encoder/steering types;
  - `estimator/wheel_imu.py`: complementary wheel + gyro estimator;
  - `runtime.py`: `SensorRobot` and `ControllerRuntime`;
  - `drivers/`: hardware protocols and JSON-lines serial codec;
  - `config.py`: portable geometry/tuning loader without pydantic.
- Added `simulator/bridge.py` (`SimRobotAPI`).
- Added simulated encoder, IMU and steering-angle models.
- Replaced `simulator/odometry.py` with the shared estimator.
- Moved shared config to `configs/`; scenarios now live in `configs/sim/`.
- Extended the boundary test to recursively reject host/physics/dashboard
  imports in `onboard/` and `algorithms/`.
- Updated README, architecture, simulation, sensors, hardware, calibration,
  status and changelog.

## Decisions

- **`onboard/` owns the contract.** The simulator implements `RobotAPI` rather
  than defining it.
- **Raw and fused data are separate.** Controllers see `sensors` and `state`;
  compatibility properties preserve old code.
- **One estimator.** The Pi and simulator run the same wheel + IMU estimator.
  EKF and lidar correction are deferred behind the same protocol.
- **Estimator tuning is separate from car geometry.** `configs/estimator.yaml`
  holds gains; vehicle/sensor YAML remain the single source for geometry and
  encoder resolution.
- **No full EKF yet.** The first estimator is a complementary filter with
  zero-velocity bias learning and slip detection. A diagnostic covariance is
  exposed so an EKF can replace it later.
