# 2026-11-04 — CMA-ES-evolved lidar gap controller

## Goal

Beat the hand-tuned furthest-gap controller on the reference one-lap scenario
(`configs/sim/awake_2027.yaml`, realistic sensors, seed 42) with zero contact,
using a sensor-only policy that can also run on the Pi.

## Done

- Added `algorithms/learned_gap.py`:
  - B1: 23-parameter structured gap controller;
  - B2: 36-beam scorer (12 features per beam, linear and residual-hidden
    variants) with a target-speed head;
  - weight loading with safe defaults, `LearnedGapController` for the registry;
  - `StructuredGapPolicy.score_surface` exposes B1's full-resolution score for
    training/debug.
- Added **Learned gap (CMA-ES)** to `algorithms/registry.py`.
- Added the host-only `training/` package:
  - `env.py`: one-lap rollout, lexicographic fitness, physics-substep contact
    monitor, speed/steering smoothness and wall-proximity penalties;
  - `vec.py`: reusable multiprocessing rollout pool;
  - `warmstart.py`: B1 expert rollouts + ridge regression onto B1's score
    surface, optional DAgger iterations, speed-capped B2 initialisation;
  - `cma_opt.py`: CMA-ES/sep-CMA-ES runner, preflight, atomic best-only export,
    default-start validation before export, status files;
  - `progress.py`: progress bar, elapsed/ETA, status text/JSON;
  - `watch.py`: live terminal view.
- Added `Simulation.physics_step_hook` for substep contact detection.
- Added optional `train` dependency (`cma>=4.5`).
- Added `tests/test_learned_gap.py` (registry, B1/B2 layout, expansions,
  shipped weights, score surface, bounded actuation).
- Added ADR-004 and `docs/experiments/EXP-2026-11-04-cmaes-gap.md`.

## Results

- Furthest-gap baseline: 25.55 s, 0 contacts (sub-rays 1); 25.82 s (sub-rays 3).
- B1 after refinement: 9.93 s, 0 contacts.
- B2a warm start (speed cap 2.7 m/s): 10.38 s, 0 contacts.
- B2a after 60 generations: **9.33 s, 0 contacts**; 9.35 s at sub-rays 3.
  Top speed 2.93 m/s, mean 2.74 m/s, minimum wall clearance 0.215 m.
- Random-track refinement (40 generations) improved the reference best to
  **9.10 s, 0 contacts**; 9.12 s at sub-rays 3, top 3.04 m/s, mean 2.83 m/s.
  Held-out random tracks: 3/6 clean, versus 2/6 for the old policy.
- Shipped `algorithms/weights/policy.npz` is the random-trained 9.10 s policy.
  `algorithms/weights/policy_b1.npz` keeps the B1 warm-start source.

## Random-track training

- Added `training.env.TrackSpec`, random-track rollout support in the
  multiprocessing pool, and `--random-track` CMA-ES options for object density,
  lane width and object size.
- The pool rebuilds each worker simulation only when the track spec changes;
  one generation normally shares a track.
- Promoted candidates are always re-validated on the reference track before
  they can be exported.
- `build_random_track` now scales crate/pole footprints with per-object jitter
  and clamps each footprint inside the lane. The dashboard exposes an
  **Object size** slider.
- Held-out check before random training: the reference B2a policy was clean on
  only 2/6 random tracks (7.93 s and 8.97 s; four contact DNFs). After
  random-track training, the shipped policy was clean on 3/6 and faster on the
  reference (9.10 s).

## Decisions

- Optimise one lap only; use physics-substep contact detection.
- Warm-start B2 by regressing onto B1's **score surface**, not a single action:
  action imitation collapsed to “drive straight” because straights dominate.
- Start B2 at a safe speed cap and let CMA-ES raise it; a slow clean lap is a
  much better search starting point than a fast crash.
- Export only a clean lap faster than the current file, then validate the
  winner at the reference start.
- Keep the learned policy's speed plan independent of the dashboard slider,
  bounded by `observation.limits.max_speed_mps`.

## Blockers / notes

- B2b (16-unit residual hidden layer, 605 parameters) was launched after the
  B2a result. A 9.03 s candidate was found from a random start offset but was
  dirty at the reference start; the end-of-run reference-start validation was
  also DNF with one contact. It was rejected. The ranking now re-validates
  every promoted candidate at the reference start before it can become “best”
  or be exported.
- The host filesystem stopped persisting some post-generation artifacts near
  the end of the B2a run (status/checkpoint stopped at gen 55 while stdout
  continued to gen 60). The exported 9.33 s policy is intact and independently
  re-verified; the transient 9.32 s candidate was not persisted.

## Next
