# 2026-10-31 — Dashboard on the standalone core

## Goal

Recreate the browser dashboard directly on the `sim-core` branch, make the car
fully configurable from code/YAML, and add a car-only studio view.

## Physical realism pass

- Added a MuJoCo digital-twin backend generated from the same `VehicleConfig`.
- Added a `World` protocol so lidar/ultrasonic models are engine-independent.
- Added the AWAKE 2027 reference scenario and hardware BOM.
- Added calibration protocol and MuJoCo backend tests.
- Kept PyBullet as a comparison backend (`--backend pybullet`).

## What changed

- Added `dashboard/` with a FastAPI backend and React/Three.js frontend.
- Added `dashboard/spec.py` to serialize the live `VehicleConfig` and
  `SensorsConfig`; the browser has no separate car model.
- Added `simulator/car_urdf.py` to generate the PyBullet URDF from the same
  vehicle config.
- Extended configs with body parts, wheel dimensions, wheel offset and typed
  sensor mounts.
- Extended lidar raycasts to 3D with mount RPY.
- Added car studio view, outliner/details UI, viewport HUD and flat engineering
  styling based on the supplied reference.
- Added `algorithms/gap_follow.py` and `algorithms/wall_follow.py` for dashboard
  demos.
- Added `examples/custom_car.py` and car/URDF regression tests.

## Decisions

- **One car definition.** A hand-written URDF would drift from YAML; generate it
  instead.
- **Sensor mounts are body-frame.** The previous mix of body-frame XY and
  ground-relative Z was confusing; all positions are now body-frame and the
  world converts PyBullet's COM pose to the body origin.
- **Car studio renders at the origin.** It is an inspection view, not a second
  physics render; it reuses the same car payload.
- **UI follows desktop tools.** Dense, square and neutral rather than neon cards.
